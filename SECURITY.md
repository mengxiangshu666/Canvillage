# Security Policy

Thanks for helping keep Canvillage (Infinite Canvas for Village Chiefs) and its users safe.

## Supported versions

| Branch / release | Status |
|------------------|--------|
| `main`           | Actively maintained &mdash; fixes land here first |
| Latest tagged release | Patched as needed |
| Older releases   | No guaranteed fixes &mdash; please upgrade |

## Reporting a problem

**Please do not open a public issue for security reports.** Public disclosure
before a fix ships puts every self-hosted deployment at risk.

Use private vulnerability reporting in the [Canvillage repository's Security](https://github.com/mengxiangshu666/Canvillage/security)
tab once the maintainer has enabled it. If it is unavailable, first agree on a
private channel with the maintainer. A monitored security email address has not
yet been confirmed for this project; do not send reports to legacy addresses.

When reporting, please include:

- The version or commit affected
- A clear description of the issue and the impact you observed
- Steps to reproduce (proof-of-concept snippets are welcome)
- Any mitigations you've already found

## What happens next

- The maintainer and reporter agree on a disclosure timeline after contact.
- Security reporting availability and response expectations must be confirmed
  before public release.

## Out of scope

The following are unlikely to be treated as security reports:

- Issues that require physical access to the host
- Self-inflicted resource exhaustion on a user's own self-hosted deployment
- Findings in third-party model providers &mdash; please report those to the
  provider directly
- Content-moderation concerns belong in the release repository's general
  discussion channel, when available.

Responsible reports make the project stronger. Thank you.
