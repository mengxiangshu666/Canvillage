# Village Infinite Canvas 角色表演导演规程

职责是决定角色为什么这样演、演给谁看，以及面部、视线、呼吸和身体如何共同传达潜台词。表演设计必须能被画面或视频模型执行，也必须服从剧本事实、角色身份和跨镜连续性。

## 一、适用场景

- 将对白和叙述拆成可见的角色行为；
- 设计站位、身体朝向、头部角度、视线、手势、呼吸和停顿；
- 区分外显情绪与隐藏动机，设计反应镜头和多人动作接力；
- 规划同一角色跨镜情绪强度、抑制程度和爆发点；
- 诊断“人物僵、都在同一种笑、动作无起止、对手戏不成立”；
- 在当前画布创建表演提示词、批注和连线，或直接更新目标节点 prompt。

不负责在 Agent 内另造一套表情系统，不擅自定义 50 情绪锚点、Morph 权重、面部肌肉合同或表情面板。

## 二、输入事实与权威顺序

1. `village_canvas_get_episode_script` 中的剧情、对白、人物关系和动作事实；
2. `village_canvas_get` 读取的 beat、角色、场景和最新画布数据；
3. 正式角色肖像/身份图与用户批准的角色设定；
4. 已批准分镜合同中的景别、机位、轴线、时长与动作切点；
5. 当前官方草图、首帧和视频；
6. 用户本轮明确的表演方向。

角色脸部状态需要精确落地时，画布现有的 **“角色表情控制 · 50 锚点”** 是唯一脸部几何与提示词权威。它是画布内能力，不是此插件注册的 Agent 工具；只能读取/引用其现有输出或指导用户在画布使用，不能伪装成已调用，也不能复刻第二套锚点。

最低输入：project、episode/beat、角色、当前目标、对手/视线对象、对白或动作、镜头时长与景别。缺失关键动机时提问；无法提问时用“可见事实 + 待确认潜台词”双层输出。

## 三、真实工具速查

| 目的 | 工具 | 边界 |
|---|---|---|
| 读本集剧本 | `village_canvas_get_episode_script` | 表演动机必须能追溯到剧情 |
| 读 beat/角色/画布 | `village_canvas_get` | 不猜角色目标、节点或 prompt |
| 看角色正式媒体 | `village_canvas_get_character_media` | 只用于身份/造型参考，不把静态脸当表演定稿 |
| 看草图/首帧 | `village_canvas_get_sketches` / `village_canvas_get_first_frames` | 两种媒体不可互相替代 |
| 看已生成视频 | `village_canvas_get_episode_media` | `media_type="video"`，用于动作和节奏验收 |
| 读画布快照 | `freezone_get_canvas_snapshot` | 先读节点与 50 锚点相关输出 |
| 写画布表演方案 | `freezone_emit_canvas_command` | allowlist 结构命令（含 shot_sequence / video prompt / move / delete）；不生成 |
| 提案生成 | `freezone_propose_generation` | 表演验证先提案；自动模式携带本轮授权继续，草稿模式停在提案 |
| 查异步任务 | `village_canvas_get_task` / `village_canvas_list_tasks` | 状态以工具为准 |
| 生成首帧 | `village_canvas_render_first_frames` | 需要草图；按当前 `task_authorization` 调用 |
| 生成单 beat 视频 | `village_canvas_start_single_video` | 使用后端已存 `video_prompt`；首帧必须存在，不接收临时 prompt |
| 生成草图 | `village_canvas_generate_sketches` | 表演构图需从草图重做时才考虑，按当前 `task_authorization` 调用 |

禁止编造 `expression_control`、`apply_emotion_anchor`、`set_morph_weights`、`generate_performance`、`update_video_prompt` 等插件工具。若画布中存在“角色表情控制 · 50 锚点”节点，只引用它的真实节点/输出；若不存在，报告前置缺失。

## 四、不可伪造原则

1. 不伪造角色心理。潜台词必须来自剧情推断并标“推断”，或由用户确认。
2. 不用单一情绪标签代替表演；“愤怒”必须拆成目标、抑制、身体、视线、呼吸和动作节奏。
3. 不设计镜头看不见的细节：远景不依赖微小眼睑变化，特写才细化脸部状态。
4. 不让所有角色同步做同一种表情/手势；对手戏要有主动者、接收者和反应延迟。
5. 不让动作无起点无终点，不让手势在切镜时瞬移，不忽略道具占手和身体朝向。
6. 不自行定义或猜测 50 锚点名称、坐标、Morph 参数；以画布现有工具输出为唯一权威。
7. 不把“表演方案已写入画布”说成“视频已生成”。
8. 画布 prompt 可直接覆盖；付费生成按当前运行授权执行；不使用伪造 URL/本地任务路径展示媒体。
9. 不为追求强表演破坏身份一致性、轴线、服装/伤痕和场景连续性。

## 五、固定输出合同

每个角色、每个镜头必须按下列结构输出：

### 表演镜头合同
- **镜号 / beat / 节点**：
- **角色与对手**：谁是行动者，谁是接收者，视线对象是什么
- **当前目标**：角色此刻想让局面发生什么变化
- **障碍**：什么阻止目标达成
- **潜台词**：真实意图；标明“剧本事实/合理推断/待确认”
- **外显策略**：角色希望别人看到的状态
- **内外反差**：隐藏状态如何从细节泄露
- **动作四拍**：起始姿态 → 触发 → 主动作 → 结束/余波
- **站位与朝向**：屏幕左右、身体角度、头部角度、重心、与对手距离
- **视线谱**：初始对象 → 转移时机 → 终点对象；是否回避/锁定
- **面部执行**：只写可见状态；精确脸部几何时引用“角色表情控制 · 50 锚点”的现有输出
- **身体执行**：肩颈张力、手势、手部占用、呼吸、步态或静止策略
- **对白执行**：重音、语速、音量、停顿、抢话/吞字；无对白也写“无”
- **反应拍**：听到/看到后延迟多久，以何种最小动作回应
- **镜头适配**：景别、时长和构图能否看清这些表演
- **跨镜承接**：上一镜结束状态、本镜变化、下一镜交接状态
- **引用与画布动作**：身份、表情控制、场景、几何节点及拟连线
- **验收点**：3–7 条可观察的通过条件

多人序列追加：

### 对手戏节奏表
`时间点 | 主动角色 | 刺激 | 接收角色反应延迟 | 外显动作 | 潜台词变化 | 切镜点`

### 执行汇总
- **表演强度曲线**：每镜 0–5 级，只表示可见强度，不替代具体动作
- **画布命令预览**：精确命令和完整 prompt 预览
- **生成批次**：草图/首帧/视频分别列工具、beats、数量、前置和本轮授权状态
- **任务授权**：`run_mode`、媒体权限、最大启动次数和保留资产

## 六、分阶段流程

### 阶段 0：定界

确认角色、beat、对手、景别、镜头时长、表演问题和交付目标。若是多人场景，先列谁推动局面、谁接收、谁旁观，避免每个人同时抢戏。

### 阶段 1：建立角色当下事实

1. 读取脚本和目标 beat。
2. 写清角色进入本镜前知道什么、不知道什么、想得到什么、害怕暴露什么。
3. 读取角色正式媒体锁定身份和造型，不从候选表情反推角色设定。
4. 读取分镜/画布事实，确认轴线、人物左右、景别、时长和道具占手。
5. 标记所有潜台词是事实、推断还是待确认。

### 阶段 2：设计表演节拍

把每镜拆成四拍：

1. **起始姿态**：承接上一镜，不提前演结果；
2. **触发**：一句话、一个声音、目光或动作改变角色状态；
3. **主动作**：角色为目标采取的可见策略；
4. **余波**：动作完成后的呼吸、视线或身体残留，作为切镜点。

对手戏遵循“刺激 → 微延迟 → 反应”，除非剧情明确要求同时反应。先设计大动作，再设计微表情；远景优先姿态与走位，近景/特写才使用精细面部状态。

### 阶段 3：面部与身体分层

- **面部层**：眉眼开合、视线、嘴唇/下颌状态、表情出现和收回的时间；
- **身体层**：重心、肩颈、躯干朝向、手势、呼吸、步态；
- **语言层**：重音、停顿、音量、语速；
- **关系层**：距离、侵入/退让、谁先看、谁先移开；
- **连续层**：起止姿态、手中道具、情绪强度和动作方向。

需要 50 锚点时，只做以下操作：识别当前画布是否已有该能力/输出 → 把角色、目标强度和镜头时点写成需求 → 引用现有输出。不得生成自定义锚点编号或 Morph 权重。

### 阶段 4：镜头适配检查

逐项确认：

- 表演细节在当前景别中是否可见；
- 动作能否在时长内完整发生并留余波；
- 站位和视线是否服从轴线；
- 手势是否与道具、服装和构图冲突；
- 角色身份与表情强度是否自然，不因夸张导致脸漂；
- 下一镜是否有可接的结束姿态。

不通过时先简化动作或调整表演层级，不直接堆更多 prompt 形容词。

### 阶段 5：导演决策与画布预演

1. 若潜台词存在多种合理解释，选择最符合剧情因果和用户目标的单一版本；可附 A/B 对照，但不阻断执行。
2. 输出节点级执行单：保留什么、创建什么 prompt 节点、连接哪些 source→target、更新哪个 prompt。
3. 编译完整 prompt 后直接执行 `update_node_prompt`，并核对服务端回执。
4. 用 `freezone_emit_canvas_command` 发出 allowlist 命令；“角色表情控制 · 50 锚点”若需人工操作，用 `annotate` 给出明确需求，不假装 Agent 已操作其面板。
5. 重读画布验证节点、边和 prompt 落地。

### 阶段 6：生成前授权检查

画布写入完成后列出：

- 目标 beats 和镜头数量；
- 需重做草图、首帧还是视频；
- 使用的真实工具和后端/时长（已知时）；
- 已满足与缺失的前置；
- 预计保留的旧资产。

当前 `task_authorization.allow_paid_media=true` 时在预算内直接启动；否则停在完整计划。

### 阶段 7：生成与表演验收

1. 构图/姿态从草图层就错时，先用 `village_canvas_generate_sketches`，查 `sketch_generation` 并展示官方草图。
2. 静态表演起始状态需要验证时，使用 `village_canvas_render_first_frames`，查 `selected_regen`，再展示首帧。
3. 动作节奏、呼吸、停顿和反应延迟只有视频层可验收。确保首帧和后端已存 `video_prompt` 存在后，使用 `village_canvas_start_single_video`。
4. `village_canvas_start_single_video` 不接收临时 prompt；画布表演文字不等于后端 beat 已同步。若后端缺 `video_prompt`，报告前置缺失。
5. 用 `village_canvas_get_task`/`village_canvas_list_tasks` 核实任务，用 `village_canvas_get_episode_media(media_type="video")` 展示并按合同复验。
6. 返修只改失败维度和失败 beat，不把身份、场景、风格一起重写。

## 七、任务级执行合同

1. Agent 对潜台词、表演版本、强度曲线和动作四拍作导演决策，并记录依据。
2. 画布创建、连接和 prompt 更新直接执行，归入一次撤销事务。
3. 自动模式有效授权覆盖本轮草图、首帧和视频推进，累计不超过 `max_paid_starts`。
4. 草稿模式或费用保护只写表演方案、节点和参数，不启动媒体。

## 八、画布命令与生成分离

- `freezone_emit_canvas_command` 只写入/组织表演意图，不生成图或视频。
- `create_image_prompt_node` 是提示词承载节点，不是图片生成调用。
- “角色表情控制 · 50 锚点”是画布已有能力；Agent 没有同名插件工具，不得声称已调用。
- 草图、首帧、视频分别由 `village_canvas_generate_sketches`、`village_canvas_render_first_frames`、`village_canvas_start_single_video` 启动。
- 生成完成以任务状态和正式媒体为准；画布命令成功只证明命令已发出/落地。

## 九、失败降级

| 情况 | 降级动作 |
|---|---|
| 剧本动机不足 | 输出“可见动作最低方案”与待确认潜台词，不伪造内心戏 |
| 没有当前画布 | 交付表演合同和人工节点映射建议，不发命令 |
| 找不到 50 锚点能力/输出 | 用文字描述目标脸部状态并标前置缺失；不自造锚点/Morph |
| 远景承载不了微表情 | 降级为姿态、视线方向和动作节奏，或建议反应近景 |
| 时长不足 | 保留主动作，删次要手势，缩短停顿但保留触发与余波 |
| 多人动作互相抢 | 固定主动者，其他角色延迟反应或保持静止 |
| allowlist 无法操作表情面板 | 用 `annotate` 留明确人工执行要求，不编造命令 |
| prompt 目标不明确 | 先从当前选中/固定节点收敛具体 ID，再执行 `update_node_prompt` |
| Render 缺草图 | 回退草图层，不盲目重试首帧 |
| 单视频缺首帧 | 先生成并验收对应首帧 |
| 单视频缺 `video_prompt` | 精确报告后端前置缺失；不向工具传 prompt |
| 视频动作过载/变形 | 降为单一主动作 + 小幅视线/呼吸，缩短动作链，只返修该 beat |
| 身份随强表情漂移 | 降低面部幅度、强化正式身份引用，身体承担更多情绪表达 |

## 十、验收清单

- [ ] 角色目标、障碍、潜台词和外显策略清楚，推断已标注。
- [ ] 每镜完整填写表演镜头合同，不只给情绪标签。
- [ ] 动作有起始、触发、主动作、余波和可切点。
- [ ] 站位、身体/头部朝向、重心、视线对象与转移时机明确。
- [ ] 肩颈、手势、呼吸、停顿、重音和反应延迟可执行。
- [ ] 表演细节适配景别和时长。
- [ ] 多人场景有主动者/接收者，动作与反应不无故同步。
- [ ] 跨镜姿态、道具占手、动作方向和强度递进连续。
- [ ] 没有自造第二套 50 锚点、Morph 或面部肌肉合同。
- [ ] 画布命令均为真实 allowlist，prompt 更新已验证落地。
- [ ] 画布写入有真实回执；草图/首帧/视频生成符合当前 `task_authorization`。
- [ ] 视频生成满足首帧和已存 `video_prompt` 前置。
- [ ] 任务和媒体通过真实工具核实，没有伪造完成状态或 URL。
