# Village Infinite Canvas 音乐与配乐

音乐不是铺满全片的背景，它负责提示身份、制造预期、改写同一动作的含义，并在对白
沉默时继续讲故事。本 Skill 处理“为什么响、什么时候响、响什么、如何收”；正式混音、
对白、口型和最终响度验收仍由 `village-canvas-post-production` 负责。

## 一、何时加载

- 成片结构已完成，但还没有音乐叙事方案；
- 需要主题曲、插曲、宣传歌、纯音乐或角色动机；
- BGM 从开场铺到结尾，没有进入、变化和退出；
- 对白与音乐争抢频段或节奏；
- 需要把同一主题在不同场景做变奏；
- 需要为生成模型编写歌词、风格、结构或器乐提示词；
- 需要规划 stems、纯音乐版、短版或平台裁剪版。

只需要音效层级和环境音时，优先加载 `village-canvas-knowledge-engine`。

## 二、事实输入

```text
成片或场次时长
故事目标与情绪弧
对白密度和静默点
关键动作、反转和切点
世界、年代、地域与器乐边界
角色身份、关系与主题
已有音乐、版权状态和禁止相似对象
目标平台、画幅、响度和交付格式
```

没有成片时，可先做 cue map，但不得声称已与画面同步；没有真实音频时，不得声称已生成
或已通过听感验收。

## 三、配乐职责分配

| 音乐形态 | 主要任务 | 典型位置 | 风险 |
|---|---|---|---|
| 主题动机 | 建立角色或世界身份 | 首次登场、关键选择 | 过早用满，后面无升级 |
| 场景配乐 | 承接情绪和空间 | 对白间隙、动作段 | 情绪重复，替演员表演 |
| 歌曲 | 承载主题文本和记忆点 | 开场、蒙太奇、片尾 | 歌词抢叙事或过度解释 |
| 环境音乐 | 建立时空和日常质感 | 城市、室内、旅途 | 频段过满，掩盖空间声 |
| 静默 | 让动作、呼吸和台词生效 | 反转前后、恐惧点 | 误把静默当空缺 |

静默必须被设计，而不是忘记放音乐。

## 四、Cue Map

先做时间轴，不先写“史诗、感动、大气”：

| Cue | 入点 | 出点 | 故事功能 | 情绪起点/终点 | 主导声音 | 对白策略 | 交付状态 |
|---|---|---|---|---|---|---|---|
| M01 | 00:00 | 00:08 | 建立异常 | 平静到不安 | 单音持续 | 无对白 | planned |

每个 Cue 至少回答：

```text
为什么从这里进入？
它让观众多知道什么或少知道什么？
结束时留下什么未解决感？
与上一 Cue 的关系是延续、变形、中断还是回声？
```

## 五、主题动机系统

一个可用动机必须短到能被记住，又能被变形：

```text
核心音程或节奏细胞
配器
角色/关系/世界含义
原始形态
积极变奏
危险变奏
失去或破碎形态
最终回收形态
```

同一动机跨场景时只改变配器、速度、调式、节奏或音区中的少量参数。不要每次重写一首
完全不同的主题，再把它们称为“统一”。

## 六、歌曲模式

只有用户明确需要歌词或歌曲时才进入歌曲模式。先写功能，再写韵脚。

```text
song_brief
叙事视角
听众位置
核心句 / 记忆钩
段落结构
每段信息增量
情绪动态弧
人声类型与语言
画面同步点
```

推荐结构仅作起点：

```text
Intro -> Verse -> Pre-Chorus -> Chorus -> Verse -> Chorus -> Bridge -> Final Chorus / Outro
```

歌曲检查：

- 副歌是否能在不看画面时仍传达主题；
- 歌词是否与画面重复说同一件事；
- 记忆钩是否每段都出现且没有过度重复；
- 第二段是否提供新信息，而不是换同义词；
- 结尾是闭合、反讽还是留白。

不得复刻受保护歌词、独特旋律或可识别歌手声音。用户要求“像某首歌/某个人”时，只提取
类型、节奏、配器或情绪功能，并改写成原创表达。

## 七、提示词与生成合同

音乐生成前先形成结构化请求：

```text
用途：主题 / 场景 / 歌曲 / 广告短版
时长与裁剪点
流派与时代
情绪起点与终点
主要器乐
人声或无人生
语言与演唱状态
速度范围
结构与段落标记
可变化段落
禁止模仿对象
输出格式与 stem 需求
```

把字段映射到当前模型目录明确支持的能力。模型只支持自由文本时，把所有要求在文本中写清；
模型支持结构化字段时，不把字段重复塞成不可解析的大段落。不得伪造 BPM、调性、声音克隆、
stem 分离或时间戳能力。

生成前展示用途、歌词状态、时长、模型、成本和分辨率/音频规格。用户未授权时不启动真实
音乐任务。

## 八、音画同步

优先同步“叙事功能”，不是机械对齐每一刀：

```text
入点：在信息出现前、同时或之后进入，决定预期方向
命中：鼓点/重音可落在动作、表情变化、转折或切点
延迟：先给画面，再给音乐解释，制造反讽或后知后觉
退出：在台词前让出空间，或在动作结束后留一个尾音
转场：延续、切断、提前进入或交叉淡化
```

对白段检查：

- 音乐是否遮住辅音和呼吸；
- 重音是否落在无意义字词；
- 副歌是否压过最关键台词；
- 是否给沉默和反应镜留出空间。

## 九、交付与后制交接

按项目需要交付：

```text
完整混音
纯音乐版
对白友好版
15s / 30s / 60s 裁切
平台画幅版本
stems：鼓、低频、和声、旋律、氛围、人声
入出点表
版权与来源说明
```

后制阶段再做：

```text
与对白、SFX、环境音混音
EBU R128 / true peak
与终片时长和帧率对账
工程 QC 回执
```

这些工程结论不在本 Skill 中预设为通过。

## 十、输出合同

```text
music_brief
cue_map
motif_system
song_plan（如需要）
generation_request
sync_plan
delivery_variants
mix_handoff
rights_notes
unverified_items
```

## 十一、验收清单

- [ ] 音乐有明确入点、功能、变化和退出。
- [ ] 主题动机可识别、可变奏、可回收。
- [ ] 歌曲比画面多提供一层信息，而不是复述画面。
- [ ] 对白、静默和关键动作有声音空间。
- [ ] 真实生成使用当前模型真实能力和真实回执。
- [ ] 没有复刻受保护歌词、旋律、声音或具体作品。
- [ ] 生成音频记录时长、格式、响度和产物哈希。
- [ ] 未做混音、听感或工程 QC 时明确标记未验证。

## 来源与边界

本 Skill 蒸馏自历史技能归档中的 `ai-music-songwriting-expert`，并吸收项目现有声音设计
边界。只保留歌曲结构、动机系统、音画同步和生成合同，不绑定某个音乐供应商或 CLI。
