## A. 工作流工具

### 1.6 Windows 本机操作只用 Python（2026-06-09）
**一句话**：PowerShell 在 Windows 下有大量隐性坑，所有本机系统操作都用 Python 脚本
**原则**：
- ✅ 所有本机文件/系统操作 → Python（pathlib/subprocess/urllib）
- ✅ 跨平台调用（Win→Linux）→ Python
- ✅ HTTP/API 调用 → Python
- ❌ 不再用 PowerShell 写复杂命令
- ⚠️ PowerShell 只用来跑 Python / 启动 GUI

**自查清单**：
- [ ] 文件读写用 pathlib，不用 Get-Content/Out-File
- [ ] 进程查询用 psutil，不用 Get-WmiObject
- [ ] 子进程用 subprocess.run([...], shell=False)
- [ ] 网络请求用 urllib/requests，不用 curl
- [ ] JSON 用 json.loads/dumps(..., ensure_ascii=False)

**工具**：`workspace/ssh/run_remote.py`

### 1.10 提示词必须写因果链（2026-06-27）
**一句话**：写"效果/结果"之前，必须先写"谁做了什么导致了这个效果"
**原则**：
- ❌ "门关上。"
- ✅ "阿强跨出门槛，转身从外面把门拉上。"
- ❌ "钢管松动。"
- ✅ "阿强抓住叉车操纵杆，叉车启动震动，钢管架晃动，一根钢管开始松动下滑。"

**自查清单**：
- [ ] 每个"发生了X"后面，问"因为Y做了Z"
- [ ] 没有因果链 = 缺，补充

### 1.17 物理行为描述 = 因果动作链（2026-06-28）
**一句话**：AI 不推断因果。描述身体部位 + 哪只手 + 身体转向 + 重力转移
**原则**：
- ❌ "阿强关门离开。"（概括词）
- ✅ "阿强的右手握住门把手，手臂向后拉，门向自己靠近直到门框完全贴合。门完全关闭。"

**描述要素**：
- 身体部位（左手/右手/左脚/右脚/腰/肩）
- 动作方向（向门外/向下/向后）
- 物理接触（鞋底咯吱/手虎口朝向）
- 重力与重心转移
- 动作后位置（站在门槛/坐在床上）

**自查清单**：
- [ ] 每个动作都有 @角色
- [ ] 每个动词都有身体部位
- [ ] 每个动作都有对象（门/药盒/打火机）
- [ ] 没有"离开/出门/相遇"这类抽象词
- [ ] 没有"站着/坐着"这类静态词

### 1.20 物理常识三校验（2026-06-28）
**一句话**：从物理世界常识推断，太多台词或太少台词都不行
**原则**：
- 维度一：字/秒校验（普通人 3-4 字/秒，虚弱 1.5-2.5 字/秒）
- 维度二：呼吸/沉默校验（每两句间至少 0.5 秒沉默）
- 维度三：环境音最低占比校验（电影对话 ≥40%，紧张追逐 ≥60%，抒情独白 ≥30%）

**自查清单**：
- [ ] 每段写完台词必须跑物理校验
- [ ] 超载 ≤15s → 重新思考意图
- [ ] 超载 >15s → 必须拆段

**工具**：`workspace/_physics_calculator.py`

### 1.21 物理常识是辅助，不是判决（2026-06-28）
**一句话**：物理校验结果是告警不是禁用。平衡两个极端
**原则**：
- ❌ 不算 → 凭感觉塞 → 段二 14s 塞 79 字 → 超载 38s
- ❌ 算死 → 必须严格 30% 环境音 → 重场戏情感台词被砍光

**阈值浮动表**：
- 日常对话：40% ±5
- 重场戏：30%（可放宽 20-30%）
- 激情对峙：45% ±5
- 内心独白：35% ±5
- 紧张追逐：60% ±10

**自查清单**：
- [ ] OVERLOAD 不立刻拆段
- [ ] 重新思考这段到底要讲什么
- [ ] 重场戏可放宽到 20-30% 环境音

## D. 写提示词

### 1.18 图片生成占 80-90% 重要性（2026-06-28）
**一句话**：先精修图片再跑视频。输入图的灯光/色调/构图决定输出视频质量
**原则**：
- 数据：image2image 16,169条 vs text2video 1,937条 = 8:1
- 三要素：灯光方向一致 / 色调统一 / 构图完整
- 流程：原始资产图 → nebula-ultra image2image 精修 → 精修后的图作为视频输入
- 分工：兄弟手动做图片精修（即梦/星绘），我不碰生图（铁律 1.8）

**自查清单**：
- [ ] 每张输入图跑视频前问：灯光方向一致吗
- [ ] 色调统一吗（暖暗调 2800-3200K）
- [ ] 构图完整吗（前景/中景/背景）

**工具**：nebula-ultra image2image

### 1.23 每个大段时间灵活配置（2026-06-28）
**一句话**：15s 硬上限是安全阈值不是强制标准。段长 = 信息量 ÷ 节奏
**原则**：
- 段长判断决策树：
  1. 列出本段所有"戏"（信息/动作/情绪/镜头）
  2. 物理校验 → 计算最小时长
  3. 加运镜变化 → 决定最终段长
  4. 段长 + 段长 ≤ 全片总时长（90s）

**实战案例**（v8.0.0 段三老楼道）：
- 戏：阿强下楼 + 老周擦肩 + 老周警告 + 阿强困惑
- 物理校验：20 字 / 2.0 字速 = 10s + 沉默 1.5s = 11.5s
- 加运镜变化 +1.5s = 13s
- 最终段长：13s

**自查清单**：
- [ ] 每段独立计算物理时长
- [ ] 不强求统一 15s
- [ ] 段长加总不能超过全片时长

**工具**：`workspace/_physics_calculator.py`

## E. 段间衔接

### 衔接决策树（待补 · 2026-06-28）
**一句话**：段与段之间用什么方式转场，按空间/时间/情绪选

**衔接方式对照表**：

| 衔接方式 | 描述 | 适用场景 |
|---------|------|---------|
| 硬切 | 一帧到下一帧，无过渡 | 强冲击、节奏快（追逐/对峙） |
| 叠化 | 两画面缓慢透明过渡 | 时间流逝/空间切换 |
| J-Cut | 声音先于画面 0.5-1s 进入 | 连续场景（同空间/时间） |
| L-Cut | 上段声音延续到下段画面 | 节奏舒缓 |
| 匹配切 | 动作/构图/形状连续 | 创意转场 |
| 闪黑 | 画面瞬间变黑 1 秒再切 | 高潮过渡 |
| 淡入淡出 | 渐变到黑/亮 | 时间跨度大 |

**短视频常用决策**：
```
同空间+连续时间 → J-Cut（声音先入）
同空间+时间跳跃 → 叠化（dissolve）
异空间+连续情绪 → L-Cut（声音延续）
异空间+情绪断裂 → 硬切（hard cut）
高潮→平复 → 闪黑（flash to black）
章节起止 → 淡入淡出（fade）
```

**v7.0.0 段间衔接现状**（已实施）：

| 段间 | 衔接方式 | 评估 |
|------|---------|------|
| 段一→段二 | 硬切 + "衔接前置指令" | ✅ 旁白结束硬切到对话 |
| 段二→段三 | J-Cut + "阿强下楼脚步声延续" | ✅ 同空间连续 |
| 段三→段四 | 叠化 + 货船汽笛 | ✅ 老周→货场空间切换 |
| 段四→段五 | 闪切 + 手电光切开画面 | ✅ 静默→动作硬切 |
| 段五→段六 | 黑屏 1 秒 | ✅ 高潮→平复 |
