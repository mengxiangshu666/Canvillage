# 剧本诊断与定向改稿

改稿前先把剧本读透，再**按清单**改，改完等确认才锁定。本技能负责前期文本层，
不代替视觉和视频生成。画布脚本节点可通过现有脚本生成器做已授权的文本改稿。

## 画布脚本节点的执行入口

先通过能力索引 `describe` / `invoke` 调用 `canvas.node.script.inspect`，读取真实
镜头表、导演规划和检查问题。用户授权“改这一镜”已经允许这次定向改稿，
不需要另问一次；讨论和诊断仍只读。

- 单镜：`canvas.node.script.submit`，`mode=rewrite_shot`，使用读取到的
  `shot_id` 和具体 `prompt`。整段使用 `mode=rewrite_sequence` 与真实 `sequence_id`。
- 规则修复：`mode=repair`；工具从当前稿重新检查，不使用编造的问题清单。
- 等待：以返回 `job_id` 调 `canvas.node.script.result`，只查已有任务，不自动重提。
- 保存：完成后 `canvas.node.script.apply` 写回来源节点；来源版本变化则先核对，
  不覆盖用户新稿。不将“任务接收”或“检查通过”报告成“已保存”。

这些入口保留片名、非目标镜头与导演规划，并经统一画布写入入口保存。
文本改稿可能调用收费文字/视觉模型；不连带启动生图、生视频或配音。
稳定镜头身份沿用现有表，SC/CR 只用于诊断说明，不重编号用户的镜头。

> 与相邻技能的分工：`village-canvas-script-integrity` 负责**事实账本与跨集连续性**
> （谁在哪、知道什么、伏笔收没收）；本技能负责**单部剧本的叙事质量诊断与改稿**。
> 两者都要读时：先跑本技能的基线解析，再交给 script-integrity 做账本比对。

## 一、阶段划分与授权边界

```
阶段 1 解析    → 逐场建立叙事基线（事实层，不含改写）
阶段 2 诊断    → 输出问题清单，分三类：客观矛盾 / 连续性风险 / 可选优化
阶段 2.5 改稿  → **只改用户批准的条目**，其余原样保留
阶段 3 锁定    → 用户明确指令后生成带版本号的锁定摘要
```

**铁律三条**：

1. **未授权不得改稿**。诊断阶段只出清单，不动原稿一个字。
2. **不得补全未确认的设定**。剧本没写的世界观、动机、人物背景，一律不替用户编；
   发现缺口就记进清单问用户。
3. **锁定只认明确指令**。用户说"锁定 v3"或"锁定 [版本号]"才算；
   "差不多了""就这样吧"这类模糊表述不算锁定请求。

## 二、阶段 1 · 解析（建立基线）

逐场提取，输出结构化基线：

| 场次 | 事实层 | 角色 | 道具 | 对白节拍 | 情绪走向 |
|---|---|---|---|---|---|

- **场次编号统一用 `SC`**（如 `SC-012`），全篇唯一、连续；
- **事实层只写剧本里明写的**：谁在场、说什么、拿什么、在哪。
- **禁止把推断写成事实**：如果某角色的动机剧本没交代，写进"缺口"，不写进"事实"；
- 逐场标注**信息释放顺序**——读者/观众在本场知道了什么，是判断悬念是否成立的基础。

## 三、阶段 2 · 诊断（导演视角）

按四类过一遍，每条问题给编号 `CR`（如 `CR-007`）：

1. **因果链**：动机→行动→结果链条是否闭合；有 A 无 B、有果无因的都记。
2. **人物弧光**：角色在剧中的变化是否可见；只有设定没有转变的记为可选优化。
3. **节奏**：信息密度是否均匀；连续高强度段落之后有没有落点。
4. **制作风险**：超出当前制作条件（场景数量、角色数量、特效）的段落标出来，
   避免后期做不到。

每条问题必须写清三件事：**现象**（哪一场、哪一行）→ **归类**（三类之一）→
**建议**（改或不改、改成什么方向）。建议要可执行，不写"建议优化节奏"这种空话。

## 四、阶段 2.5 · 定向改稿

只按用户批准的 CR 清单改，逐条对应：

- 每处修改给出 **修改说明**：改成什么、为什么、依据哪条 CR；
- 给出 **连带影响检查**：这条改动是否影响后续场次的事实、伏笔或角色知识状态；
- 给出 **回归结论**：改完后原本能对上的地方是否还对得上。

未批准的条目**原样保留**，不"顺手优化"。

## 五、阶段 3 · 锁定

用户明确发出锁定指令后：

- 生成带版本号的锁定摘要（版本号、锁定范围、生效时间）；
- 锁定后原稿视为只读，后续改稿走新版本，不覆盖已锁定版本；
- 锁定摘要要能被 `village-canvas-script-integrity` 当作账本基线引用。

## 六、验收清单

- [ ] 场次用 SC 编号且全篇唯一连续
- [ ] 事实层与导演推断严格分开，推断标为"缺口"而非事实
- [ ] 问题按三类归档，每条有 CR 编号 + 现象 + 归类 + 可执行建议
- [ ] 改稿只覆盖用户批准条目，未批准条目原样保留
- [ ] 每处改稿有修改说明、连带影响检查与回归结论
- [ ] 锁定只在用户明确指令后发生，摘要含版本号
- [ ] 全程没有替用户补全未确认的设定

## 来源与边界

- 方法论来源：`libtv AI导演-剧本诊断改稿`（上游 528 次使用）。上游原文支持
  DOCX/PDF/FDX 输入与文件输出；本技能支持对话内文本与当前画布脚本节点，
  不直接读写任意文件，也不声称支持这些格式。
- **刻意不抄**：上游的三阶段编号（阶段 2.5）保留为工作习惯，但锁定摘要格式换成本仓
  自己的版本合同；CR/SC 编号是本仓统一口径，不沿用上游可能存在的其它前缀。
- 不涉及视觉风格、分镜或视频提示词——那些分别由 `village-canvas-visual-style`、
  `village-canvas-storyboard`、`village-canvas-prompt-framework` 负责。
- 诊断只产出结论；用户已授权的画布脚本改稿经上述真实能力和统一派发入口写回。
