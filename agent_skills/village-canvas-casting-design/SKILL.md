# Village Infinite Canvas 选角与角色概念

选角不是“长得好看”，而是判断一张脸和一副身体能否持续承担这个角色的行动、关系、
秘密与变化。本 Skill 负责在正式角色设定表之前做选角决策和概念验证；
`village-canvas-character-workflow` 负责把胜出的形象做成正式参考资产。

## 一、何时加载

- 只有角色小传或几段剧本，还没有可拍摄的形象；
- 同一个角色有几个视觉方向，需要选择而不是全部生成；
- 演员/角色的年龄、体态、气质与剧情功能不匹配；
- 需要正面、侧面、背面、3/4 视图和表情测试；
- 角色要在多个镜头、服装状态和情绪跨度中保持可识别；
- 广告、短剧、动画或游戏项目需要先做概念选角再进入量产。

若用户已经确认唯一角色形象，只需要正式设定表，直接加载 `village-canvas-character-workflow`。
若要解决成片中的身份漂移，加载 `village-canvas-continuity`。

## 二、事实输入

开始选角前建立一份最小角色合同：

```text
角色 ID / 故事功能
年龄感 / 性别呈现 / 地域与语言背景
职业 / 阶层 / 生活痕迹
性格表层与真实底色
与主角或关键角色的关系
观众第一眼必须读到什么
剧情中必须发生的身体变化
项目画幅、风格和拍摄条件
不能使用的真实人物或受保护形象
```

缺项处理：

- 剧本没有写外貌，不得凭空宣布为正式事实；输出“候选方向 + 待确认项”；
- 用户给的是感觉词，先把感觉词翻译成脸型、体态、视线、声音与动作习惯；
- 用户指定真实演员时，默认只做“角色适配分析”；未经明确授权，不克隆真人脸、声音或
  制作可误导为本人出演的媒体；
- 选角参考可以借鉴类型与气质，不去复制某个可识别演员的独特组合。

## 三、六个选角维度

每个候选只按以下六维打分，不做笼统的“合适/不合适”：

| 维度 | 要回答的问题 | 可见证据 |
|---|---|---|
| 叙事功能 | 这张脸能否承载角色的核心矛盾？ | 静止肖像、第一眼气质 |
| 表演跨度 | 能否从克制演到爆发而不换脸？ | 四段表情/姿态测试 |
| 视觉辨识 | 远景、侧脸、背影是否仍可认出？ | 剪影、侧脸、背身 |
| 世界适配 | 是否符合时代、职业、阶层和类型？ | 服装、发型、皮肤、道具 |
| 镜头适配 | 近景、中景、运动镜是否能成立？ | 特写、中近景、动态帧 |
| 可复现性 | 关键锚点能否被文字和参考图稳定描述？ | 锚点表、跨模型重测 |

任何一项为致命缺口时，不进入正式资产制作。不要用更多细节掩盖根本选错。

## 四、候选包

默认只做 2-3 个方向，每个方向是一份可比较的候选包，不是三堆零散美图：

```text
candidate_id
一句话选角判断
角色功能匹配
面部锚点
身体与动作锚点
造型与生活痕迹
镜头优势
镜头风险
最不适合的戏
需要验证的未知项
```

候选之间必须真正不同：脸型、骨架、体态、生活痕迹或表演气质至少改变两项。
只换发色和衣服不算新候选。

## 五、五轮 Look Test

每轮只解决一个问题，上一轮失败就不要进入下一轮。

### 1. 剪影轮

去掉服装细节和背景，只看头肩比、下颌、鼻梁、发际线、体态与站姿。

通过条件：不看正脸也能和同项目其他角色区分。

### 2. 正面轮

使用中性光、中性表情和简洁背景，检查眼距、脸长、骨相、皮肤质感与职业痕迹。

通过条件：不需要解释，观众就能读到角色的一两个主要特质。

### 3. 多角度轮

检查正面、侧面、背面、3/4 视图以及头身比例。四视图只有在同一角色身份稳定时才成立。

通过条件：侧面和背面仍保留同一套身份锚点。

### 4. 表演轮

至少测试四种状态：

```text
中性 / 压抑 / 决意 / 失控边缘
```

每种状态只改变可解释的肌肉、视线、呼吸和姿态，不换成另一张脸。

通过条件：情绪变化明显，身份没有漂移。

### 5. 环境轮

把胜出形象放进真实主场景、主光条件和主服装状态，测试近景、中景、远景及运动姿态。

通过条件：角色能从角色板进入故事世界，而不是只在白底上成立。

## 六、身份锚点合同

胜出后，只保留可跨镜复用的锚点：

```text
脸型与下颌
眉眼关系与眼形
鼻梁与鼻头
嘴唇与牙齿可见特征
发际线、发量与自然发型
肤色与皮肤质感
头身比与肩颈关系
标志性姿态或动作习惯
一到两个不可丢失的造型信号
```

不把临时表情、单次光线、摄影机夸张透视写进身份锚点。

## 七、模型无关的提示词

选角提示词按以下顺序编译：

```text
角色身份与时代
  -> 面部与身体锚点
  -> 生活痕迹和职业信息
  -> 中性服装或指定服装
  -> 中性背景
  -> 视角与镜头
  -> 光线与色彩
  -> 画幅与输出用途
  -> 负向漂移
```

如果当前模型支持参考图、风格参考、角色表或结构化参数，只使用模型目录明确声明的能力；
不得伪造 `sref`、ControlNet、种子或一致性强度。

多角度测试必须显式写清：

```text
front / side / back / three-quarter
四个视角保持同一头身比、服装状态和身份锚点
视图之间留出清晰间隔，不互相遮挡
```

## 八、生成与回执边界

- 先生成低成本草图时，也必须来自真实图片模型和真实任务回执；
- 未授权的图片生成不自动触发，计划、提示词和预算预览不算已出图；
- 每轮只保留能回答当前问题的产物，不把失败图冒充候选；
- 真实生成后记录 provider、model、任务终态、产物哈希和尺寸；
- 用户选中的候选才进入正式角色资产制作。

## 九、交接给角色工作流

交接包必须包含：

```text
approved_candidate_id
selection_rationale
identity_anchors
approved_references
rejected_drift
wardrobe_states
performance_tests
scene_lighting_conditions
open_questions
```

`village-canvas-character-workflow` 从 approved references 制作正式设定表和比例锁定，
不再重新选一次角色。

## 十、输出合同

```text
casting_brief
candidate_packages
look_test_results
approved_candidate
identity_anchor_contract
generation_evidence
handoff_to_character_workflow
unverified_items
```

## 十一、验收清单

- [ ] 选角先服务叙事功能，不先服务漂亮或明星相似度。
- [ ] 候选方向有实质差异，不是同一张脸换衣服。
- [ ] 剪影、正面、多角度、表演和环境测试按顺序完成。
- [ ] 身份锚点可从文字和参考图双向复现。
- [ ] 真实人物、脸和声音没有在未授权时被复制。
- [ ] 只调用模型目录声明的能力，不伪造参考和一致性机制。
- [ ] 真实生成有任务回执，未生成的项目明确标记未验证。
- [ ] 胜出形象以结构化交接包进入正式角色资产制作。

## 来源与边界

本 Skill 蒸馏自历史技能归档中的 `ai-casting-director`、
`character-orthographic-prompt-pro`、`sss-character-concept-architect`。
只保留选角判断、五轮验证、身份锚点和多视图合同，不复制旧平台模板、题材展示或外部运行时。
